## Why It's Fundamentally Impossible

### The Browser Security Model

The W3C Fetch specification defines a list of **forbidden header names** that JavaScript
CANNOT set via `fetch()` or `XMLHttpRequest.setRequestHeader()`. These include:

- `Referer` — always generated by browser from page origin
- `Origin` — always generated by browser from page origin
- `Host` — always derived from the request URL
- `Content-Length` — always computed from body
- `User-Agent` — managed by browser (extensions can change, JS cannot)
- `Cookie` — managed by browser cookie jar (only same-domain cookies are sent)

When JavaScript attempts to set these headers, the browser **silently ignores** the value
and uses its own generated value instead. No error is thrown — the header just doesn't
get set to the desired value.

### Why This Blocks mzfi Zero-Egress

mzfi's CDN (sbcdnw.hakunaymatata.com) has Referer anti-leech that accepts ONLY:
- mzfi.me, movieboxhd.net, netfilm.world, moviebox.ph, movie-box.co, themoviebox.xyz

For browser-direct access from nobar-stream.vercel.app:
1. Browser sends `Referer: https://nobar-stream.vercel.app/` → **REJECTED (429)**
2. JS tries `fetch(url, {headers: {Referer: 'https://mzfi.me/'}})` → browser ignores, sends real origin → **REJECTED (429)**
3. Service Worker tries same → uses fetch API → browser ignores → **REJECTED (429)**
4. `<video referrerpolicy="no-referrer">` → sends NO Referer → **REJECTED (429)**

There is NO browser-side way to make the browser send `Referer: https://mzfi.me/`
when the page is loaded from `nobar-stream.vercel.app`.

### Why vidlink.pro HLS (sacdn) Works But mzfi DASH (sbcdnw) Doesn't

| CDN | Auth Method | Referer Check | Browser Can Access? |
|---|---|---|---|
| sacdn (vidlink HLS) | CloudFront signed URL (in URL query) | ❌ None | ✅ YES — no Referer needed |
| cacdn (subtitles) | CloudFront signed URL (in URL query) | ❌ None | ✅ YES — no Referer needed |
| sbcdnw (mzfi DASH) | Aliyun edge-auth (URL query works) | ✅ **Strict** | ❌ NO — Referer required |
| bcdnxw (mzfi MP4) | Aliyun sign+t (URL query) | ✅ **Strict** | ❌ NO — Referer required |
| bcdn (vidlink MP4) | Aliyun sign+t (URL query) | ❌ None | ❌ NO — **UA anti-bot** (428) |

CloudFront (AWS) CDNs don't check Referer → browser can access directly.
Aliyun CDNs DO check Referer → browser can't bypass.

## Recommendation

The current implementation is **already optimal** for what's possible without a server:

1. **vidlink.pro HLS** (~15% of movies) → zero-egress ✅
2. **All subtitles** (vidlink + mzfi) → zero-egress via cacdn ✅
3. **mzfi primary** → /api/proxy (needs server, but this is the PRIMARY provider with largest catalog)
4. **vidlink.pro TV fallback** → /api/proxy (fixed in this session, now works!)
5. **Embed iframe** → emergency fallback (zero-egress but loses Nobar UI)

**To eliminate the remaining ~90% egress (mzfi), deploy the Cloudflare Worker.**
This is the ONLY way to make mzfi zero-egress. There is no browser-side bypass,
and there never will be — it's a fundamental security boundary.
