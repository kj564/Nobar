**Task ID:** RE-vidsrc-harder
**Agent:** main

## TL;DR

vidsrc.sh uses a **multi-layer protection system** that makes server-side stream URL extraction **impossible**:
1. Cloudflare Turnstile gate (browser-only challenge)
2. IP-bound JWT tokens (rotated per request)
3. ChaCha20-encrypted stream URLs (WASM decryption in browser)
4. Anti-devtools (kills video if devtools opened)

**Bypass options:**
- **iframe embed** — works (no X-Frame-Options), shows their UI + possible ads, **ZERO server bandwidth**
- **Server-side extraction** — NOT viable (Turnstile blocks)
- **Direct MP4** — NOT available (all streams behind encryption + Turnstile)

## Architecture

```
User browser
  │
  ├─→ vidsrc.sh/embed/movie/{tmdbId}     (outer page, no X-Frame-Options)
  │     │
  │     ├─→ /vs_src.php?type=movie&id={id}
  │     │     └─→ {src: "https://stellarconductornexus.com/embed/movie/{id}?vs={token}"}
  │     │
  │     └─→ iframe: stellarconductornexus.com/embed/movie/{id}?vs={token}
  │           │
  │           ├─→ window.CFG = {playerUrl: "/embed/player/movie/{id}?vs={token2}"}
  │           │
  │           └─→ iframe: /embed/player/movie/{id}?vs={token2}
  │                 │
  │                 ├─→ window.CONFIG = {
  │                 │     api: "https://data.vidsrc.sh/api.php?...&stream_urls",
  │                 │     apiToken: "{JWT IP-bound}",
  │                 │     turnstile: true,
  │                 │     turnstileSiteKey: "0x4AAAAAAFQ2DUc3K6LVn4hL",
  │                 │     turnstileVerify: "/embed/verify.php"
  │                 │   }
  │                 │
  │                 ├─→ Cloudflare Turnstile challenge (browser JS only)
  │                 │
  │                 ├─→ POST /embed/verify.php (Turnstile token → session token)
  │                 │
  │                 ├─→ GET data.vidsrc.sh/api.php?...&stream_urls
  │                 │     Headers: Authorization: Bearer {apiToken}
  │                 │     └─→ {stream_urls: "encrypted_base64", vs: {wasm_url: "..."}}
  │                 │
  │                 └─→ vsdec.js (WASM ChaCha20 decryptor)
  │                       └─→ decrypts stream_urls → [MP4/m3u8 URLs]
  │
  └─→ <video src="{decrypted CDN URL}"> plays directly
```

## Section 2: API endpoints

### 2.1 vs_src.php (CORS: credentials=true, NO allow-origin)
```
GET https://vidsrc.sh/vs_src.php?type=movie&id=135397
→ {"src": "https://stellarconductornexus.com/embed/movie/135397?vs={token}"}
```
- Returns the inner player URL with signed `vs=` token
- CORS: `access-control-allow-credentials: true` but NO `allow-origin` → browser can't fetch cross-origin
- Must be fetched server-side or same-origin

### 2.2 data.vidsrc.sh/api.php (CORS: allow-origin=*)
```
GET https://data.vidsrc.sh/api.php?type=movie&tmdb=135397
→ {"status_code":"200","data":{"title":"Jurassic World 2015","imdb_id":"tt0369610","file_name":"...","backdrop":"..."}}
```
- Metadata only (no stream URLs)
- CORS: `access-control-allow-origin: *` — browser CAN fetch directly

### 2.3 data.vidsrc.sh/api.php?...&stream_urls (REQUIRES TOKEN)
```
GET https://data.vidsrc.sh/api.php?type=movie&tmdb=135397&stream_urls
Headers: Authorization: Bearer {apiToken}
→ 403 "invalid api token" (without valid token)
→ 200 {stream_urls: "encrypted_base64", vs: {wasm_url: "..."}}  (with valid token + Turnstile)
```
- `apiToken` is JWT with `{exp, ip, n}` — IP-bound + time-limited (~5 min)
- Token generated by inner player page (`/embed/player/movie/{id}?vs={token}`)
- `stream_urls` is base64 ChaCha20 nonce||ciphertext, decrypted by vsdec.js WASM

### 2.4 /embed/verify.php (Turnstile verification)
```
POST https://stellarconductornexus.com/embed/verify.php
Body: {turnstile_token: "...", ...}
→ Returns session token that authorizes API call
```
- Cloudflare Turnstile challenge must be solved first
- Requires browser JS execution (invisible challenge, but still browser-only)

## Section 3: Stream URL extraction — NOT VIABLE server-side

Tested server-side extraction:
1. ✅ Fetch vs_src.php → get stellarconductornexus.com URL
2. ✅ Fetch stellarconductornexus.com outer page → get playerUrl with new vs= token
3. ✅ Fetch inner player page → extract apiToken from CONFIG
4. ❌ Call data.vidsrc.sh with apiToken → 403 "invalid api token"

**Why 403?** The apiToken contains `ip: "8.212.10.159"` (our server's IP). The API validates:
- Token signature (HMAC) — valid
- Token IP matches requester IP — might match
- Turnstile session — MISSING (we didn't solve the Turnstile)

The Turnstile requirement (`turnstile: true` in CONFIG) means the API call needs BOTH the apiToken AND a Turnstile-verified session cookie/token. Without solving the Turnstile in a browser, the API rejects the request.

## Section 4: vsdec.js — ChaCha20 WASM decryptor

The `stream_urls` field in the API response is encrypted:
- Format: base64(nonce || ciphertext) using ChaCha20
- Key: per-5-minute-window, delivered as WASM module
- `vs: { w: <window_id>, wasm_url: "https://.../<w>.wasm?_=<ts>" }`
- vsdec.js compiles the WASM, instantiates fresh per call, decrypts the string

This is browser-only — requires WebAssembly + the WASM module URL from the API response.

## Section 5: Anti-devtools

Both outer and inner pages include `disable-devtool.js`:
- If devtools is opened, the video is killed (`v.pause(); v.removeAttribute('src'); v.load()`)
- Page redirects to `about:blank`
- This prevents manual inspection of network requests / stream URLs

### Recommendation

**For zero server bandwidth:** Use iframe embed as a fallback source.
- When mzfi/vidlink sources fail → fallback to `<iframe src="https://vidsrc.sh/embed/movie/{tmdbId}">`
- User sees vidsrc.sh's player (poster + play button)
- Turnstile solved invisibly by Cloudflare JS
- Video bytes go direct: browser → CDN (ZERO Vercel egress)

**For best UX:** Keep current mzfi/vidlink proxy as primary.
- Native Nobar player (no ads, custom controls, subtitle menu)
- Cost: ~2GB egress per view on Vercel Pro ($20/month for 1TB = ~500 views)

**Hybrid approach (recommended):**
1. Primary: mzfi MP4 via proxy (best UX, ad-free)
2. Fallback: vidlink MP4 via proxy (when mzfi unavailable)
3. Last resort: vidsrc.sh iframe embed (zero bandwidth, shows their UI)
